# Generate each kind of Event of standalone Actor types and Manager types as a private function that update, onAdded, onKeyPressed, and onCollisionDetected only call

**Decision (user, 2026-11-02):** detect and report. G05 lands as planned, and Creator names every Kotlin Block that relies on what changes, so nothing breaks silently.

**Challenged:** amended — a family hook taking `kubriko: Kubriko` needs that import in every child file that overrides it (G04 made imports per file); a standalone edge Event's Kotlin Blocks also lose the edge handling's locals (`box`, `sceneSettings`, `topLeft`, `bottomRight`), as family hooks never had them; the Kotlin Block's scope is worded per Event, since each of the three names exists only in some; `everyEvent` lives in `actors/EveryBlockTypes.kt` since G02; the docs are the actors package guide's (creator/CLAUDE.md has no Kotlin Blocks or Manager types section since ae027ca3e); `onAdded`'s condition stays `ActorTypeFeatures.overridesOnAdded`.

**Kind:** performance  ·  **Severity:** low  ·  **Platforms:** desktop (JIT), all (method size)
**Findings:** ACT-4  ·  **Depends on:** G04
**Files:** `actors/EventFunctions.kt` (new: the `Hooks` naming moved out of `ActorFamilyCodeGenerator`), `actors/ActorClassEmitter.kt`, `actors/ActorFamilyCodeGenerator.kt`, `actors/ManagerTypeCodeGenerator.kt`, `actors/BlockCodeGenerator.kt` (`appendEvents`, `appendTimer`, `appendKeyHandling` go), `actors/ActorClassCode.kt`, `actors/BlockDefinition.kt` (Kotlin Block `@Description`), tests `actors/ActorTypeCodeGeneratorTest.kt`, `actors/ActorFamilyCodeGeneratorTest.kt`, `actors/ManagerTypeCodeGeneratorTest.kt`, `actors/EveryBlockTypes.kt` (test source set, `everyEvent`'s comment), `creator/src/test/resources/generated/*.kt.txt` (regenerated), `actors/CLAUDE.md` (the "Generated Kotlin compiles" bullet), `context/HealthChecks.kt`, `context/HealthFinding.kt`, `creator/src/main/composeResources/values/strings.xml`, the workspace opening code that reports to the console (`WorkspaceController`/K09b's factory), `context/HealthChecksTest.kt`

## Problem

A standalone Actor type inlines every Timer's, every-frame, and edge Event's Blocks into `update()`, every collision Event's into `onCollisionDetected`, and every key Event's into `onKeyPressed` (G04's `INLINE` dispatch, today `ActorTypeCodeGenerator.generateActorType`):

```kotlin
appendLine("    override fun update(deltaTimeInMilliseconds: Int) {")
appendLine(REMOVED_GUARD)
timers.forEach { timer -> appendTimer(timer, timerEvents.filter { it.timer == timer }, scope) }
appendEvents(definition.events.filter { it.type == EventType.EVERY_FRAME }, depth = 2, scope = scope)
appendLine(MOVEMENT_LINE)
if (edgeEvents.isNotEmpty()) appendEdgeHandling { appendEvents(edgeEvents, depth = 3, scope = scope) }
```

Manager types do the same in `onInitialize`, `onUpdate`, and `onKeyPressed` (`ManagerTypeCodeGenerator.generateManagerType`). HotSpot doesn't JIT-compile a method over 8000 bytecode bytes (`DontCompileHugeMethods`), so a type with a few hundred Blocks runs its whole `update()` interpreted on desktop, and the 64 KB method limit is reachable: the integration test already gives every Block to only three keys "which would make a method too large to compile" (`ProjectTemplateIntegrationTest.everyEvent`). Families don't have the problem: each kind of Event is a `protected open` hook (`ActorFamilyCodeGenerator.Hooks`).

## Fix

1. Move `Hooks`' naming (`ADDED`, `EVERY_FRAME`, `EDGE`, `key(...)`, `collision(...)`, `timer(...)`, `Hook(signature, call)`, `of(event)`) into `actors/EventFunctions.kt`, add `GAME_STARTED = "onGameStarted"` for Managers, and use it for standalone types, family roots, and Managers alike. Standalone and Manager functions are `private fun`, family hooks stay `protected open fun`; G04's `INLINE` dispatch goes, and so do `BlockCodeGenerator.appendEvents`/`appendTimer`/`appendKeyHandling` once nothing calls them (the Event comments `eventComment(...)` move into the functions, or go if the function name says it: keep "// When added to the Scene" etc. only if tests need it, and say which in the commit).
2. Dispatchers only call: `update` = removed guard, each Timer's countdown calling `on<Timer>Finished(...)` (`appendTimerCountdown`, `isCommented = false`), `onEveryFrame(...)`, movement, edge handling calling `onEdgeTouched(...)`, mask update; `onKeyPressed` = pause guard and `Key.X -> onKeyPressedX()` per key; `onCollisionDetected` = guard and `is X -> if (!other.isRemoved) onCollisionWithX(other)`; `onAdded` (still written exactly when `ActorTypeFeatures.overridesOnAdded` holds, unchanged) = lookups, then `onAddedToScene(kubriko)` if that function exists; a Manager's `onInitialize` = guard, `actorManager.add(this)` if it has key Events, `onGameStarted(kubriko)`; its `onUpdate` = guard, Timers, `onEveryFrame(deltaTimeInMilliseconds)`. A function exists only for an Event kind (and key, other type, Timer) that has an Event with Blocks, as the family hooks for an Event kind exist only when an Event of it exists; keep the family's rule unchanged.
3. **What Kotlin Blocks keep in scope.** Today a standalone type's Kotlin Block sits inside `update(deltaTimeInMilliseconds: Int)`, `onAdded(kubriko: Kubriko)`, and so on, and `PropertyNaming` reserves `deltaTimeInMilliseconds`, `kubriko`, `other`, `key`, `index`, and `collidables` for that reason. So the functions take what their dispatcher has that an Event can use: every-frame, edge, and Timer functions `deltaTimeInMilliseconds: Int` (edge also the four `isTouching...Edge: Boolean`, as the family hook does now), added-to-Scene and game-started functions `kubriko: Kubriko`, collision functions `other: <class>`. Family hooks take the same parameters (generated overrides change with them), so a Kotlin Block compiles the same in a standalone type and in a family, which isn't true today (a family hook has no `deltaTimeInMilliseconds`). `key`, `index`, and `collidables` leave scope (a per-key function knows its key; the loop variables were never meant for Blocks), and so do the edge handling's locals in a standalone edge Event (`box`, `sceneSettings`, `topLeft`, `bottomRight`; a family's edge hook never had them); keep all of them reserved. None of them was ever in the Kotlin Block's documented scope, but note in the lane report that a Kotlin Block using one stops compiling. Primitive and object parameters don't allocate, so the engine's no-allocation rule holds.
   **Imports of the parameters.** `Kubriko` (the added-to-the-Scene and game-started functions) is a parameter type: with G04's per-file imports, the file of every class that declares or overrides `onAddedToScene(kubriko: Kubriko)` imports `com.pandulapeter.kubriko.Kubriko`, a child's file too (today a child's `override fun onAddedToScene()` needs nothing). Collision parameters name generated classes of the same package, and `Int`/`Boolean` need no import. Test it: `ActorFamilyCodeGeneratorTest.aChildOverridingTheAddedHookImportsKubriko` (a child with an added-to-the-Scene Event: `generate(child)` contains `override fun onAddedToScene(kubriko: Kubriko) {` and `import com.pandulapeter.kubriko.Kubriko\n`).
4. **`return` in a Kotlin Block.** A Kotlin Block is wrapped in `run { ... }` (`BlockCodeGenerator.actorBlockLines`, "Each Kotlin Block gets a scope of its own"), and `run` is inline, so today a `return` in it returns from `update()` (or `onKeyPressed`, `onCollisionDetected`, `onAdded`): it skips the rest of the frame (movement, edges, the mask update) or the remaining collisions. After this change it returns from the Event's function: it skips the rest of that Event and of the later Events of the same kind (and key, Timer, other type) in the same type, which is what a family hook already does. Keep the `run { }` wrapper (two Kotlin Blocks may declare the same name). Update the Kotlin Block's `@Description` with: "`return` ends this Event's Blocks, and those of the type's later Events of the same kind." and, after its "In scope" list: "Also deltaTimeInMilliseconds (an Int) in every-frame, edge-touched, and Timer Events, kubriko in added-to-the-Scene and game-started Events, and other (the Actor collided with) in collision Events." The description reaches the AI through `get_block_catalog`. In the actors package guide's "Generated Kotlin compiles" bullet, after "Kotlin Blocks get their own `run { }` scope": "inside a function per kind of Event, so a `return` ends only that Event's Blocks".
5. Integration test: reword the comment in `EveryBlockTypes.everyEvent` (G02 moved it to `actors/EveryBlockTypes.kt`): "Every key, though only a few with every Block, to keep the project small to compile", behaviour unchanged.
6. Keep every generator function under the 120-line limit P01 makes the size check apply to members, and the files under 500.

**Reporting Kotlin Blocks the change affects (decided):** add a health check finding (`HealthChecks`, a new `HealthFinding` kind with its string) for every Kotlin Block, in an Actor type or a Manager type, whose code uses `return` (outside a nested `fun`/lambda it declares itself, as far as `KotlinIdentifiers`' tokenizing can tell) or names one of the locals that leave scope (`key`, `index`, `collidables`, `box`, `topLeft`, matched as identifiers outside strings and comments with `KotlinIdentifiers`). Each finding names the type, Event, and Block (`Ball#1.2`) and says what to change (`return` now ends only this Event; the local is no longer available — read it from `body`/`kubriko` instead). The same findings go to the console once when a project opens (one status line per type, not per Block), and `get_health_checks` returns them, so the AI can fix them. Keep the check a pure function over the model (no file reads), so it runs wherever health checks run today.
